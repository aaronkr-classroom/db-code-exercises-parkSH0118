## 연습문제

### 1번

문제> 다음 중 이상 현상에 대한 설명이 잘못된 것은?

1. 이상 현상은 관계 DB를 조작할 때 데이터의 중복으로 인해 발생하는 문제를 의미한다.
2. 삽입 이상은 어떤 데이터를 삽입하면 불필요한 데이터도 함께 삽입되는 현상이다.
3. 삭제 이상은 어떤 데이터를 삭제하면 유용한 데이터도 함께 삭제되는 현상이다.
4. 갱신 이상은 중복된 데이터 가운데 일부만 갱신되어 데이터의 불일치가 발생하는 현상이다.

답> 2번

삽입 이상은 “어떤 데이터를 삽입하면 불필요한 데이터도 함께 삽입되는 현상”이 아니라, 불필요한 데이터를 함께 삽입하지 않으면 필요한 데이터를 삽입할 수 없는 현상이다.

---

### 2번

문제> 이상 현상의 원인과 해결 방법에 대한 설명이 잘못된 것은?

1. 이상 현상의 근본 원인은 성능 향상을 위해 데이터가 중복되었기 때문이다.
2. 이상 현상의 근본 원인은 속성 간에 존재하는 여러 개의 종속 관계를 하나의 릴레이션으로 표현했기 때문이다.
3. 이상 현상을 해결하려면 속성 간의 여러 종속 관계를 분해해야 한다.
4. 이상 현상을 해결하려면 하나의 종속 관계를 하나의 릴레이션으로 표현해야 한다.

답> 1번

이상 현상의 근본 원인은 성능 향상을 위한 의도적 중복이 아니라, 속성 간 종속성을 충분히 고려하지 않아 여러 종속 관계가 하나의 릴레이션에 섞였기 때문이다.

---

### 3번

문제> 함수적 종속에 대한 설명이 잘못된 것은?

1. 함수적 종속은 릴레이션이 갖고 있는 이상 현상을 발견하기 위해 속성 간의 종속 관계를 규명하는 개념이다.
2. 속성 X의 각 값에 대해 속성 Y의 값이 오직 하나만 연관되면 속성 X는 속성 Y에 함수적으로 종속된다고 한다.
3. 함수적 종속을 `X → Y`로 표현했을 때 X를 결정자, Y를 종속자라고 부른다.
4. 한 릴레이션에 속한 속성 간의 복잡한 함수적 종속 관계를 쉽게 이해할 수 있도록 그림으로 표현한 것이 함수적 종속 다이어그램이다.

답> 2번

`X`의 값이 정해질 때 `Y`의 값이 하나로 결정되면, `Y`가 `X`에 함수적으로 종속된다. 즉 올바른 표현은 `X → Y`이고, `X`는 결정자, `Y`는 종속자이다.

### 6번

문제> `도서(ISBN, 제목, 발행일, 저자id, 저자국적)` 릴레이션의 함수적 종속 관계가 다음과 같이 표현되었다. 이 릴레이션이 만족하는 정규형은 무엇인가? 답에 대한 이유도 설명하시오.

```text
ISBN → 제목
ISBN → 발행일
ISBN → 저자id
ISBN → 저자국적
저자id → 저자국적
```

답> 제2 정규형

이 릴레이션의 기본키는 `ISBN`이다. 기본키가 단일 속성이므로 부분 함수적 종속은 발생하지 않는다. 따라서 제2 정규형은 만족한다.

하지만 `ISBN → 저자id`이고 `저자id → 저자국적`이므로, `ISBN → 저자국적`은 이행적 함수적 종속이다. 기본키가 아닌 속성인 `저자국적`이 기본키에 이행적으로 종속되므로 제3 정규형은 만족하지 못한다.

따라서 이 릴레이션이 만족하는 가장 높은 정규형은 제2 정규형이다.

### 7번

문제> 역정규화가 필요한 이유에 대해 설명하시오.

답> 역정규화는 정규화로 인해 릴레이션이 많이 분해되어 조인 연산이 자주 발생하고, 그 결과 검색 질의의 응답 시간이 길어질 때 필요하다.

정규화는 데이터 중복과 이상 현상을 줄이는 장점이 있지만, 원하는 정보를 얻기 위해 여러 릴레이션을 조인해야 하므로 성능이 저하될 수 있다. 이때 심각한 성능 저하가 발생하면, 이미 분해된 릴레이션을 다시 통합하여 데이터 중복을 일부 허용하더라도 검색 속도를 높일 수 있다. 이것이 역정규화이다.

단, 역정규화는 갱신 이상이나 무결성 관리 비용 증가를 유발할 수 있으므로 꼭 필요한 경우에만 수행해야 한다.

---

### 8번

문제> 역정규화에 대한 설명으로 잘못된 것은?

1. 응답시간이 감소한다.
2. 갱신 이상이 발생할 수 있다.
3. 릴레이션 수를 줄이기 위해 이미 분해된 둘 이상의 릴레이션을 통합하는 작업이다.
4. 무결성 보장을 위한 비용이 증가한다.

답> 제공된 보기 기준으로는 잘못된 설명이 확인되지 않는다.

네 보기는 모두 역정규화에 대한 옳은 설명이다.

- 역정규화는 조인을 줄여 검색 응답시간을 줄이기 위해 수행한다.
- 데이터 중복이 다시 생기므로 갱신 이상이 발생할 수 있다.
- 이미 분해된 둘 이상의 릴레이션을 통합하는 방식으로 수행될 수 있다.
- 중복 데이터의 일관성을 따로 관리해야 하므로 무결성 보장 비용이 증가한다.

따라서 이 문항은 원문 보기 중 하나가 잘못 입력되었을 가능성이 있다. 만약 1번 보기가 “응답시간이 증가한다”였다면 1번이 오답이 된다.

### 9번

문제> 다음 회원관리 릴레이션은 헬스클럽의 회원 정보와 회원 관리를 담당하는 트레이너 정보가 함께 저장된 릴레이션이다. 이 릴레이션에 포함된 이상 현상이 잘못 설명된 것은?

1. 삽입 이상: 새로운 트레이너를 채용했는데 아직 담당할 회원이 없는 경우, 이 트레이너의 정보를 삽입할 수 없다.
2. 삽입 이상: 새로운 회원을 삽입할 때 담당 트레이너가 지정되지 않았으면 삽입할 수 없다.
3. 갱신 이상: 트레이너의 연락처가 갱신된 경우, 일부 회원 정보만 갱신하면 데이터의 불일치가 발생한다.
4. 삭제 이상: 1011(이정이) 회원의 정보를 삭제하면, 3번(김은미) 트레이너에 대한 정보도 함께 삭제된다.

답> 2번

기본키는 `회원번호`이므로, 새로운 회원 자체는 `회원번호`를 기준으로 삽입할 수 있다. 담당 트레이너가 아직 지정되지 않았다면 트레이너 관련 속성은 나중에 입력하거나 NULL로 둘 수 있다.

반면 1번, 3번, 4번은 회원 정보와 트레이너 정보가 하나의 릴레이션에 함께 저장되어 생기는 이상 현상 설명으로 타당하다.

### 10번

문제> 9번 문제에 제시된 회원관리 릴레이션의 함수적 종속 관계를 분석하여 정규화하는 과정을 완성하시오.

답>

#### 릴레이션 스키마

```text
회원관리(회원번호, 회원이름, 연락처, 가입일자, 담당트레이너, 트레이너이름, 트레이너연락처)
```

#### 기본키

```text
회원번호
```

#### 대체키

```text
없음
```

#### 함수적 종속

```text
회원번호 → (회원이름, 연락처, 가입일자, 담당트레이너, 트레이너이름, 트레이너연락처)
담당트레이너 → (트레이너이름, 트레이너연락처)
```

#### FDD
    
```text
회원번호 → 회원이름
회원번호 → 연락처
회원번호 → 가입일자
회원번호 → 담당트레이너
담당트레이너 → 트레이너이름
담당트레이너 → 트레이너연락처
```

즉, 다음 이행적 함수 종속이 존재한다.

```text
회원번호 → 담당트레이너 → (트레이너이름, 트레이너연락처)
```

#### 정규형

| 단계 | 내용 |
|---|---|
| 1NF | 모든 속성이 원자값이므로 1NF를 만족한다. |
| 2NF | 기본키가 단일 속성 `회원번호`이므로 부분 함수적 종속이 없어 2NF를 만족한다. |
| 3NF | `회원번호 → 담당트레이너 → 트레이너이름, 트레이너연락처` 이행적 함수 종속을 제거해야 한다. |

#### 릴레이션 분해

```text
회원(회원번호, 회원이름, 연락처, 가입일자, 담당트레이너(FK))
트레이너(담당트레이너, 트레이너이름, 트레이너연락처)
```

### 11번

문제> `멘토링하다` 릴레이션의 함수적 종속 관계를 분석하여 정규화하는 과정을 완성하시오.

답>

#### 릴레이션 스키마

```text
멘토링하다(멘티_num(FK), 멘토_id, 멘토소속, 멘토연락처, 멘토링장소, 멘토링요일, 멘토링시간)
```

#### 기본키

```text
멘티_num
```

#### 대체키

```text
없음
```

#### 함수적 종속

```text
멘티_num → (멘토_id, 멘토소속, 멘토연락처, 멘토링장소, 멘토링요일, 멘토링시간)
멘토_id → (멘토소속, 멘토연락처)
```

#### FDD

```text
멘티_num → 멘토_id
멘티_num → 멘토링장소
멘티_num → 멘토링요일
멘티_num → 멘토링시간
멘토_id → 멘토소속
멘토_id → 멘토연락처
```

즉, 다음 이행적 함수 종속이 존재한다.

```text
멘티_num → 멘토_id → (멘토소속, 멘토연락처)
```

#### 정규형

| 단계 | 내용 |
|---|---|
| 1NF | 모든 속성이 원자값이므로 1NF를 만족한다. |
| 2NF | 기본키가 단일 속성 `멘티_num`이므로 부분 함수적 종속이 없어 2NF를 만족한다. |
| 3NF | `멘티_num → 멘토_id → 멘토소속, 멘토연락처` 이행적 함수 종속을 제거해야 한다. |

#### 릴레이션 분해

```text
멘토링하다(멘티_num(FK), 멘토_id(FK), 멘토링장소, 멘토링요일, 멘토링시간)
멘토(멘토_id, 멘토소속, 멘토연락처)
```

참고: 첨부 이미지에서 `멘토링시간` 일부 값은 워터마크에 가려져 보이지만, 정규화 분석에는 영향을 주지 않는다.

### 12번

문제> `동아리가입하다` 릴레이션의 함수적 종속 관계를 분석하여 정규화하는 과정을 완성하시오.

답>

#### 릴레이션 스키마

```text
동아리가입하다(학번(FK), 동아리번호, 동아리명, 동아리지도교수명, 가입일자, 역할)
```

#### 기본키

```text
{학번, 동아리번호}
```

#### 대체키

```text
없음 또는 제공 자료만으로는 확인 불가
```

#### 함수적 종속

```text
{학번, 동아리번호} → (동아리명, 동아리지도교수명, 가입일자, 역할)
동아리번호 → (동아리명, 동아리지도교수명)
```

#### FDD

```text
{학번, 동아리번호} → 가입일자
{학번, 동아리번호} → 역할
동아리번호 → 동아리명
동아리번호 → 동아리지도교수명
```

즉, `동아리명`과 `동아리지도교수명`은 복합키 전체가 아니라 복합키의 일부인 `동아리번호`에만 종속되므로 부분 함수적 종속이 존재한다.

#### 정규형

| 단계 | 내용 |
|---|---|
| 1NF | 모든 속성이 원자값이므로 1NF를 만족한다. |
| 2NF | `동아리번호 → 동아리명, 동아리지도교수명` 부분 함수적 종속을 제거해야 한다. |
| 3NF | 2NF로 분해한 뒤 별도의 이행적 함수 종속이 확인되지 않으므로 3NF도 만족한다. |

#### 릴레이션 분해

```text
동아리가입하다(학번(FK), 동아리번호(FK), 가입일자, 역할)
동아리(동아리번호, 동아리명, 동아리지도교수명)
```
