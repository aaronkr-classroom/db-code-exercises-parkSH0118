## 연습문제

### 1번

문제> 다음 중 이상 현상에 대한 설명이 잘못된 것은?

1. 이상 현상은 관계 DB를 조작할 때 데이터의 중복으로 인해 발생하는 문제를 의미한다.
2. 삽입 이상은 어떤 데이터를 삽입하면 불필요한 데이터도 함께 삽입되는 현상이다.
3. 삭제 이상은 어떤 데이터를 삭제하면 유용한 데이터도 함께 삭제되는 현상이다.
4. 갱신 이상은 중복된 데이터 가운데 일부만 갱신되어 데이터의 불일치가 발생하는 현상이다.

답> 2번

삽입 이상은 어떤 데이터를 삽입할 때 불필요한 데이터도 함께 삽입되는 현상이 아니다. 필요한 데이터를 삽입하려고 할 때, 불필요한 데이터를 함께 넣지 않으면 삽입 자체가 어려워지는 현상이다. 따라서 2번 설명이 잘못되었다.

---

### 2번

문제> 이상 현상의 원인과 해결 방법에 대한 설명이 잘못된 것은?

1. 이상 현상의 근본 원인은 성능 향상을 위해 데이터가 중복되었기 때문이다.
2. 이상 현상의 근본 원인은 속성 간에 존재하는 여러 개의 종속 관계를 하나의 릴레이션으로 표현했기 때문이다.
3. 이상 현상을 해결하려면 속성 간의 여러 종속 관계를 분해해야 한다.
4. 이상 현상을 해결하려면 하나의 종속 관계를 하나의 릴레이션으로 표현해야 한다.

답> 1번

이상 현상의 근본 원인은 성능 향상을 위해 일부러 데이터를 중복시켰기 때문이 아니다. 속성 간의 종속 관계를 충분히 고려하지 않아 여러 종속 관계가 하나의 릴레이션에 함께 표현되었기 때문에 발생한다. 따라서 1번 설명이 잘못되었다.

---

### 3번

문제> 함수적 종속에 대한 설명이 잘못된 것은?

1. 함수적 종속은 릴레이션이 갖고 있는 이상 현상을 발견하기 위해 속성 간의 종속 관계를 규명하는 개념이다.
2. 속성 X의 각 값에 대해 속성 Y의 값이 오직 하나만 연관되면 속성 X는 속성 Y에 함수적으로 종속된다고 한다.
3. 함수적 종속을 `X → Y`로 표현했을 때 X를 결정자, Y를 종속자라고 부른다.
4. 한 릴레이션에 속한 속성 간의 복잡한 함수적 종속 관계를 쉽게 이해할 수 있도록 그림으로 표현한 것이 함수적 종속 다이어그램이다.

답> 2번

`X → Y`에서 X는 결정자이고 Y는 종속자이다. 즉 X의 값이 정해질 때 Y의 값이 하나로 결정되면, Y가 X에 함수적으로 종속된다고 표현한다. 2번은 종속 관계의 방향을 반대로 설명했으므로 잘못된 설명이다.

답> 정보의 무손실

### 6번

문제> `도서(ISBN, 제목, 발행일, 저자id, 저자국적)` 릴레이션의 함수적 종속 관계가 다음과 같이 표현되었다. 이 릴레이션이 만족하는 정규형은 무엇인가? 답에 대한 이유도 설명하시오.

```text
ISBN → 제목
ISBN → 발행일
ISBN → 저자id
ISBN → 저자국적
저자id → 저자국적
```

답> 제2 정규형

도서 릴레이션의 기본키는 `ISBN`이다. 기본키가 단일 속성이므로 복합키의 일부에만 종속되는 부분 함수적 종속은 발생하지 않는다. 따라서 제2 정규형은 만족한다.

하지만 `ISBN → 저자id`이고 `저자id → 저자국적`이므로 `ISBN → 저자국적`은 이행적 함수적 종속 관계가 된다. 기본키가 아닌 속성인 `저자국적`이 기본키에 이행적으로 종속되기 때문에 제3 정규형은 만족하지 못한다.

따라서 이 릴레이션이 만족하는 가장 높은 정규형은 제2 정규형이다.

### 7번

문제> 역정규화가 필요한 이유에 대해 설명하시오.

답>

정규화를 수행하면 데이터 중복과 이상 현상을 줄일 수 있다. 하지만 릴레이션이 지나치게 많이 분해되면 원하는 정보를 조회할 때 여러 릴레이션을 조인해야 한다. 이 경우 질의 처리 시간이 길어지고 시스템의 응답시간이 증가할 수 있다.

역정규화는 이러한 성능 저하를 줄이기 위해 필요하다. 이미 분해된 릴레이션을 다시 통합하거나 일부 중복 데이터를 허용하여 조인 횟수를 줄이고 검색 성능을 높이는 방법이다.

다만 역정규화를 하면 데이터 중복이 다시 발생할 수 있으므로 갱신 이상이나 무결성 관리 비용이 증가할 수 있다. 따라서 역정규화는 성능 개선이 꼭 필요한 경우에 제한적으로 적용해야 한다.

---

### 8번

문제> 역정규화에 대한 설명으로 잘못된 것은?

1. 응답시간이 감소한다.
2. 갱신 이상이 발생할 수 있다.
3. 릴레이션 수를 줄이기 위해 이미 분해된 둘 이상의 릴레이션을 통합하는 작업이다.
4. 무결성 보장을 위한 비용이 증가한다.

답> 정답 없음

주어진 보기들은 모두 역정규화에 대한 옳은 설명이다.

역정규화는 검색 성능을 높이고 응답시간을 줄이기 위해 수행할 수 있다. 또한 이미 분해된 둘 이상의 릴레이션을 통합하는 방식으로 이루어질 수 있다. 하지만 데이터 중복이 다시 발생할 수 있으므로 갱신 이상이 생길 수 있고, 무결성을 보장하기 위한 관리 비용도 증가할 수 있다.

따라서 주어진 보기 중 잘못된 설명은 없으며, 이 문항은 보기 오류가 있는 것으로 판단된다.

### 9번

문제> 다음 회원관리 릴레이션은 헬스클럽의 회원 정보와 회원 관리를 담당하는 트레이너 정보가 함께 저장된 릴레이션이다. 이 릴레이션에 포함된 이상 현상이 잘못 설명된 것은?

1. 삽입 이상: 새로운 트레이너를 채용했는데 아직 담당할 회원이 없는 경우, 이 트레이너의 정보를 삽입할 수 없다.
2. 삽입 이상: 새로운 회원을 삽입할 때 담당 트레이너가 지정되지 않았으면 삽입할 수 없다.
3. 갱신 이상: 트레이너의 연락처가 갱신된 경우, 일부 회원 정보만 갱신하면 데이터의 불일치가 발생한다.
4. 삭제 이상: 1011(이정이) 회원의 정보를 삭제하면, 3번(김은미) 트레이너에 대한 정보도 함께 삭제된다.

답> 2번

회원관리 릴레이션의 기본키는 `회원번호`이다. 따라서 새로운 회원은 회원번호를 기준으로 삽입할 수 있다. 담당 트레이너가 아직 정해지지 않았다면 트레이너 관련 속성은 나중에 입력하거나 비워둘 수 있다.

반면 1번은 아직 담당 회원이 없는 트레이너 정보를 독립적으로 삽입하기 어렵다는 점에서 삽입 이상에 해당한다. 3번은 트레이너 연락처가 중복 저장되어 일부만 수정될 경우 불일치가 발생하는 갱신 이상이다. 4번은 특정 회원을 삭제했을 때 그 회원에게만 나타나 있던 트레이너 정보까지 사라질 수 있으므로 삭제 이상에 해당한다.

따라서 잘못 설명된 것은 2번이다.

### 10번

문제> 9번 문제에 제시된 회원관리 릴레이션의 함수적 종속 관계를 분석하여 다음 표에 정규화하는 과정을 완성하시오.

답>

#### 릴레이션 스키마

```text
회원관리(회원번호, 회원이름, 연락처, 가입일자, 담당트레이너, 트레이너이름, 트레이너연락처)
```

#### 기본키

```text
회원번호
```

#### 대체키

```text
없음
```

#### 함수적 종속

```text
회원번호 → 회원이름, 연락처, 가입일자, 담당트레이너, 트레이너이름, 트레이너연락처
담당트레이너 → 트레이너이름, 트레이너연락처
```

#### FDD

```text
회원번호 → 회원이름
회원번호 → 연락처
회원번호 → 가입일자
회원번호 → 담당트레이너
담당트레이너 → 트레이너이름
담당트레이너 → 트레이너연락처
```

#### 정규화 과정

| 정규형 | 내용 |
|---|---|
| 1NF | 모든 속성이 원자값이므로 제1정규형을 만족한다. |
| 2NF | 기본키가 `회원번호` 하나이므로 부분 함수적 종속이 없어 제2정규형을 만족한다. |
| 3NF | `회원번호 → 담당트레이너 → 트레이너이름, 트레이너연락처`의 이행적 함수적 종속이 있으므로 이를 제거해야 한다. |

#### 릴레이션 분해

```text
회원(회원번호, 회원이름, 연락처, 가입일자, 담당트레이너(FK))
트레이너(담당트레이너, 트레이너이름, 트레이너연락처)
```

답>


#### 기본키

```text
멘티_num
```

#### 대체키

```text
없음
```

#### 함수적 종속

```text
멘티_num → 멘토_id, 멘토소속, 멘토연락처, 멘토링장소, 멘토링요일, 멘토링시간
멘토_id → 멘토소속, 멘토연락처
```

#### FDD

```text
멘티_num → 멘토_id
멘티_num → 멘토링장소
멘티_num → 멘토링요일
멘티_num → 멘토링시간
멘토_id → 멘토소속
멘토_id → 멘토연락처
```

#### 정규화 과정

| 정규형 | 내용 |
